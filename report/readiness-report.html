The problem

Budgets, transit changes, rezonings and new facilities are explained in long staff reports, often published shortly before the meeting. Affected residents find out late, can't tell how it touches them, and miss the chance to speak. Municipal Agents drafts a plain brief from the city's own documents; code checks every quote is on its page, and a named staff member approves each statement. Lenses add transit access, lifecycle cost, commitments and housing.

Data and resources needed

  • Staff reports, agendas, budgets, plans as text PDFs; per decision, a clerk-checked timeline and map area.
  • GTFS, OpenStreetMap, building permits, Statistics Canada households.
  • A trained reviewer per brief; light IT; a capped model API key.

How another municipality adapts it

  1. cities/<id>.json: map, languages, notice page, clerk, GTFS, open data. ~1 h
  2. PDFs into data/sources; npm run sources. ~1 h
  3. data/decisions/<id>.json, clerk-checked. ~2–4 h each
  4. Local GTFS, OpenStreetMap, permits (5 stages). ~1–3 days
  5. Model and spend caps; deploy the container. ~½ day
  6. Train reviewers. ~1 h

Times are estimates. Text PDFs and public GTFS need no code changes.

Needed before real use

Accuracy and review time measured in a pilot; a WCAG 2.2 AA audit; a privacy impact assessment; a Canadian-hosted model; OCR for scanned PDFs; a written clerk sign-off procedure.

Who would use it

  • Residents, no account: renters, owners, riders, seniors, students, parents, people with a disability, newcomers.
  • Clerks, communications: start a brief, review each statement, publish.
  • Planners: transit, cost, housing lenses from open data.
  • Councillors, groups: one cited link with the dates to take part.

Privacy and the law

  • No personal data by design. No resident accounts; only public documents go to the model. Questions are kept without identity TODO(verify) no IP but are public, so we ask people not to type personal details.
  • MFIPPA. A municipality may collect personal information only if a statute authorizes it, for law enforcement, or if necessary to a lawfully authorized activity, with notice (ss. 28(2), 29(2)).4 Still do a privacy impact assessment.
  • Data residency. The Gemini API is a US service; paid-tier content is not used to improve Google's products.5 For production: Vertex AI in Canada, which lists Gemini 3.5 and 3.8 Flash but not 3.6,6 or an on-premises model.
  • Bill 194. Ontario's Enhancing Digital Security and Trust Act, 2024 lets the province require prescribed public sector entities that use AI (municipalities can be prescribed) to inform the public, keep an accountability framework, manage risk and have a person oversee it.1,2 No regulation yet does so for municipal AI.3 The prototype already discloses AI use, names a human approver and keeps a public log.

What residents should know

  • AI drafts; a named staff member approves each statement.
  • Not the official notice: each page links to it, and it prevails.
  • Every number links to its page. The AI can be wrong; it never says what to think.
  • Questions are public, not tied to you. Translations are by machine TODO(verify).
  • Errors: "Report an error" or the clerk TODO(verify).
