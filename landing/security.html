Security and trust

Trust is the product.

A city can't publish text it hasn't checked, and a resident shouldn't have to take an AI's word for anything. Here is how each safeguard works, and what's live today versus offered for pilots.

  • Live in the demo today
  • Pilot option offered in a pilot agreement
  • Target or Planned not done yet

Accuracy

Every statement earns its place.

Live

Citations checked in code

An agent can only record a statement through a tool that checks it on the spot: each citation's quote must be found on the page it names, in that source, after normalising spacing and line breaks. If it isn't, the statement is rejected and the agent is told where the quote really is, or the closest line on that page. A model never grades its own citations.

Live

Staff publish, statement by statement

Agent output is a draft until a named staff member reviews every statement: approve, edit (and the citation is checked again) or reject, with a note. Until then the brief says, in plain words, "Draft: not yet reviewed by city staff". The demo briefs are unreviewed drafts today: no municipality has reviewed them.

Live

Neutral by design

Agents explain, lay out the trade-offs on both sides and say what the documents don't answer. They never decide and never tell anyone what to think. Every brief is labelled "Not the official notice" and links to the notice that is.

Live

Plain language, measured

Briefs aim for a grade 8 reading level or lower. The grade is computed in code (Flesch-Kincaid) and shown on the brief, even when it misses the target.

Accountability

A record that can't be edited quietly.

Live

Hash-chained public record

Every brief, citation check, question, answer, review, approval and dollar spent is appended to a log. Each entry's SHA-256 hash covers the previous entry's hash, so changing or deleting any past entry breaks every hash after it. The database refuses updates and deletes, and anyone can re-check the whole chain in their browser on the public record.

hash(n) = SHA-256( hash(n-1) + entry(n) ) entry(n) = { seq, at, actor, kind, decision, payload }

The honest limit: whoever controls the server could rebuild the whole chain. Publishing the latest hash somewhere outside the city's sole control closes that gap; it's planned.

Live

Spend caps and a public spend page

Each agent run stops at 40 model calls or US$0.50, and the public site at US$5 a day. Every call's tokens and cost are logged and shown on the spend page, with an estimate of energy use.

Live

Open code, one container

The code is on GitHub. The agents are a small loop a city's IT team can read, with plain-language skill files staff can review. The service is one process in one container, with one settings file per city.

Privacy and data

Public data in. No personal data kept.

Live

No resident accounts, no tracking

Residents never sign up. There are no analytics or advertising trackers. Questions are logged on the public record with no identifier, and IP addresses stay in memory only for the rate-limit window, never written. Because questions are public, residents are asked not to type personal details. This site stores one thing in your browser, your light or dark choice, and sends nothing; the contact form only opens a pre-filled GitHub issue for you to post.

Live

Public documents only

Agents read what the city has already published: reports, budgets, notices, agendas and open data. Each source is listed with its publisher, date, licence and link.

Planned

Canadian data residency

Today the service and its record run on one server in Toronto, and the demo's model calls go to a hosted model in the United States. Guaranteed Canadian storage on every plan, model processing in Canada on City and Region plans, and an on-premises option with a model of the city's choice are planned, and would be written into each pilot agreement.

Planned

Staff sign-in

In the demo, staff tools sit behind a shared passcode. A sign-in for each staff member, with roles, and single sign-on with the city's identity provider are on the roadmap.

Pilot option

A procurement-ready trust package

For pilots: a privacy impact assessment template (Ontario's MFIPPA in mind), AI disclosure text for your website, and an algorithmic impact assessment in the style of the federal tool.

Planned

SOC 2

We don't have a SOC 2 or ISO 27001 report yet. A SOC 2 Type I readiness assessment and audit are planned for 2027, with a penetration test summary in the procurement package.

Accessibility

Readable by everyone it affects.

Target

WCAG 2.2 AA and AODA

We build and test to WCAG 2.2 Level AA: keyboard and screen-reader use, visible focus, contrast in light and dark themes, a high-contrast mode, and reduced motion when asked. That goes beyond the WCAG 2.0 Level AA that the Accessibility for Ontarians with Disabilities Act requires of designated public-sector websites. An independent audit is part of our plan; it hasn't happened yet.

Live

In residents' languages

The interface is in English and French. A translator agent renders briefs and answers in other languages from the staff-approved text, keeping every citation.

Report a problem

Found something wrong?

For a security vulnerability, please open a private advisory on GitHub. Our security.txt lists the same contacts.

For a wrong statement in a brief, or anything else, contact us. Corrections are made by staff and land on the public record like everything else.
